# printkit v0.1 — Plan 1: Scaffold + Data Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up printkit as a real, harness-complete Next.js + Supabase repo (seeded from paykit, not templatecentral:scaffold's stock Next.js flow — see Global Constraints), with vendor auth, and the full v0.1 data model (`print_jobs`, `kit_api_keys`, `admins`/`is_admin`/`admin_audit`) so later plans (cross-kit integration, dashboard, Android bridge) have a working foundation to build on.

**Architecture:** Copy paykit's repo wholesale (closest sibling: bearer-secret `/api/v1/*` API, own Supabase schema, no e-commerce baggage), strip every paykit-specific file (payments, checkout, bookings, pricing, feedback), rename `paykit` → `printkit` everywhere (schema name, package name, types), keep the harness (CI, husky, `.claude/`, AGENTS.md/CLAUDE.md skeleton) verbatim then rewrite its content for printkit. Auth and vendor-session guard are copied near-verbatim (generic Supabase email/password + Google OAuth, no paykit logic in them). Data model mirrors paykit's `kit_api_keys` and `admins`/`is_admin`/`admin_audit` migrations exactly (same grant/RLS shape), with a new `print_jobs` table per this kit's own spec.

**Tech Stack:** Next.js 16 (App Router, Turbopack) · TypeScript strict · Tailwind v4 · shadcn/ui (new-york) · Zod · `@supabase/ssr` 0.10.x + `@supabase/supabase-js` 2.48.x · Vitest + `@testing-library/*` · Stryker (advisory mutation testing) · pnpm 11 · Node ≥24 · Vercel (region `sin1`) · `@merqo/ui` (github:cljiahao/merqo-ui#v0.18.0, current tag as of 2026-08-21).

**Spec:** `docs/superpowers/specs/2026-08-21-printkit-v0.1-design.md`

## Global Constraints

- Stack/deployment matches every sibling kit exactly: Next.js + Supabase (`@supabase/ssr`), own `printkit` schema in the shared Supabase project, own Vercel deploy, bearer-secret HTTP API (`kit_api_keys` pattern, same as paykit's `/api/v1/*`).
- **Do not use `templatecentral:scaffold`'s stock `nextjs` flow** — it installs better-auth + Drizzle and breaks RLS (confirmed: paykit's own AGENTS.md states this explicitly, and its output pulls in `@tanstack/react-query`/`axios`/`pino`/`lefthook`/a route-logging enforcement script that no real Supabase kit in this portfolio carries). Seed by copying paykit's repo instead — same precedent paykit itself used seeding from qkit, and loopkit before it.
- `@merqo/ui` for shared components — same convention every kit already follows.
- No shared code library for the print/Bluetooth logic itself — printkit-only, never imported by another kit (out of scope for this plan; applies to Plan 4).
- Pin exact dependency versions for anything new or changed — do not rewrite paykit's pre-existing caret ranges unasked (existing project convention).
- `print_jobs.job_type` is designed to hold future job types beyond `'label'` — do not hardcode a single-value enum without room to extend (use a `check` constraint listing valid values, add to the list later, don't redesign the column).
- `admin_audit`: service-role insert/select only, no update/delete grant even for service-role; RLS admin-read-only (exact quote from spec's Data model section) — mirror paykit's `admins`/`is_admin()`/`admin_audit` pattern (`0006_paykit_admin.sql`), not a vendor-readable audit log.
- No persisted bridge-device table for v0.1 (Presence covers the live signal — Plan 4's concern, not this plan's).
- TypeScript strict, no `any`, no `@ts-ignore`. Validate all user input with Zod at every boundary.
- Authorization lives in RLS policies, not app code.
- Every `/api/v1/*` route (built in Plan 2) will need `verifyKitAuth` before touching the database — this plan builds that helper, doesn't yet call it from a route.
- After editing the schema, update both `supabase/migrations/` and `src/lib/types.ts` in the same task.

- [ ] **Step 2: Write `0001_printkit_core.sql`**

```sql
create schema if not exists printkit;

create table printkit.print_jobs (
  id           uuid primary key default gen_random_uuid(),
  vendor_id    uuid not null references auth.users(id) on delete cascade,
  job_type     text not null default 'label' check (job_type in ('label')),
  payload      jsonb not null,
  status       text not null default 'queued' check (status in ('queued', 'sent', 'printed', 'failed')),
  source_kit   text not null,
  source_ref   text not null,
  created_at   timestamptz not null default now(),
  printed_at   timestamptz
);
create index print_jobs_vendor_idx on printkit.print_jobs (vendor_id, created_at desc);
create index print_jobs_source_idx on printkit.print_jobs (source_kit, source_ref);

create table printkit.kit_api_keys (
  kit_slug    text primary key,
  secret_hash text not null,
  created_at  timestamptz not null default now()
);

-- RLS: a vendor reads (not writes) only their own print_jobs. Writes are
-- service-role + bearer-secret only (POST /api/v1/print-jobs from qkit,
-- and the dashboard's manual-reprint action) — same shape as paykit's
-- transactions table.
alter table printkit.print_jobs   enable row level security;
alter table printkit.kit_api_keys enable row level security;

create policy print_jobs_vendor_select on printkit.print_jobs
  for select using ((select auth.uid()) = vendor_id);

-- kit_api_keys: no policy at all — only service_role (which bypasses RLS)
-- may ever touch it. No grants below give authenticated/anon any access.

grant select on printkit.print_jobs to authenticated;
grant all on printkit.print_jobs, printkit.kit_api_keys to service_role;
```

- [ ] **Step 3: Write `0002_printkit_admin.sql`**

```sql
-- Platform-operator admin: an internal allow-list of admins and an
-- immutable audit trail of disputable vendor/admin actions. Mirrors
-- paykit's 0006_paykit_admin.sql + 0009_paykit_admin_audit_immutable.sql,
-- folded into one migration since printkit has no pre-existing admin_audit
-- rows to migrate around.

create table printkit.admins (
  user_id    uuid primary key references auth.users(id) on delete cascade,
  created_at timestamptz not null default now()
);

create or replace function printkit.is_admin(p_uid uuid)
returns boolean language sql security definer stable set search_path = '' as $$
  select exists (select 1 from printkit.admins where user_id = p_uid);
$$;

create table printkit.admin_audit (
  id         uuid primary key default gen_random_uuid(),
  admin_id   uuid not null references auth.users(id),
  action     text not null,
  target_id  uuid,
  detail     jsonb,
  created_at timestamptz not null default now()
);
create index admin_audit_created_idx on printkit.admin_audit (created_at desc);

alter table printkit.admins      enable row level security;
alter table printkit.admin_audit enable row level security;

create policy admins_admin_select on printkit.admins
  for select using (printkit.is_admin((select auth.uid())));
create policy admin_audit_admin_select on printkit.admin_audit
  for select using (printkit.is_admin((select auth.uid())));

grant select on printkit.admins, printkit.admin_audit to authenticated;
grant select, insert on printkit.admin_audit to service_role;
grant all on printkit.admins to service_role;
grant execute on function printkit.is_admin(uuid) to anon, authenticated, service_role;

-- admin_audit is service-role insert/select only, no update/delete grant
-- even for service_role (see grant above — update/delete simply never
-- granted, closing off tampering at the grant level independent of RLS).
```

```ts
import { createHash, timingSafeEqual } from "node:crypto";
import { createServiceClient } from "@/lib/supabase/server";

export function hashApiKey(secret: string): string {
  return createHash("sha256").update(secret, "utf8").digest("hex");
}

export async function verifyKitAuth(
  request: Request,
): Promise<{ kitSlug: string } | null> {
  const header = request.headers.get("authorization") ?? "";
  const prefix = "Bearer ";
  if (!header.startsWith(prefix)) return null;

  const token = header.slice(prefix.length);
  const sep = token.indexOf(":");
  if (sep <= 0) return null;
  const kitSlug = token.slice(0, sep);
  const secret = token.slice(sep + 1);
  if (!kitSlug || !secret) return null;

  const supabase = await createServiceClient();
  const { data, error } = await supabase
    .from("kit_api_keys")
    .select("secret_hash")
    .eq("kit_slug", kitSlug)
    .maybeSingle();
  if (error || !data) return null;

  const provided = Buffer.from(hashApiKey(secret));
  const expected = Buffer.from(data.secret_hash);
  const ok =
    provided.length === expected.length && timingSafeEqual(provided, expected);
  return ok ? { kitSlug } : null;
}
```
